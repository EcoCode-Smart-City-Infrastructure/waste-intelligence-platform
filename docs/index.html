    What each view does

    • Live NYC Data — pulls DSNY tonnage, organics, diversion and facility data straight from NYC Open Data (Socrata). Falls back to a labelled sample only if the network call fails.
    • Bins & Routes — add, update and collect demo bins, then build a nearest-neighbour collection route.
    • Forecasting — ports the platform's real algorithm: current fill cycle, least-squares trend, R², time-to-full, and z-score anomaly check.
    • Knowledge Graph — the repo's real 31-node / 55-edge W2RKG sample, searchable and clickable.
    • Contamination — the backend's exact stream-acceptance map, with manual material tagging (the YOLOv11 model itself needs the backend service).
    • Kepler 3D Map — real Kepler.gl geospatial operations: demo fleet, 3D fill-density grid, urgent collection route arcs, live tonnage by borough, and 48-hour fill tracking, with Kepler's own layer / filter / time controls. Opens on kepler.html.

      Forecasting & anomaly detection

      Same math as services/forecasting/app.py: drop pre-collection history after a fill drop over 30 points, fit a least-squares line to the current cycle, report slope, R² and time-to-full. Anomaly = z-score of the latest reading against its own history.

      How to read this

      • Slope is fill points per hour from the current cycle only. A collection (drop > 30 points) restarts the cycle, exactly as the backend does.
      • R² near 1 means the trend fits well; near 0 means the forecast is shaky — treat time-to-full as a guide, not a promise.
      • Anomaly flags a latest reading more than 2 standard deviations from its cycle mean. The backend raises 422 when history is too thin; here you get the same warning in plain words.

      Waste-to-Resource Knowledge Graph

      The repo's real sample graph (cloud_platform/analytics/kg/data/w2rkg_nyc_sample.json): 31 nodes, 55 edges — now drawn as a circle, because nothing here ends at a landfill. Waste becomes a process, a process becomes a resource, demand pulls that resource back through a facility, and the facility takes waste again.

      Circular navigation tap a segment

      The ring is the menu. Each segment filters the graph to one node type; the centre shows what you are looking at. “All” restores the full graph. The search and type dropdown below still work exactly as before.

      Animated resource flow waste → process → resource → demand → back again

      Pick a pathway and press Play. The dot travels the loop, and the steps below update with that pathway's real conversion metrics — not a generic animation. The loop-closure step is the point: demand is served by an actor who operates a facility that accepts waste, so the circle closes.

      Node colours group by type. Edges are now soft biomorphic curves, not straight lines — they are the graph's real edges, only drawn the way a flow looks. Click a node to highlight its neighbours; a traced path animates along its curves.

      Pick a node

      Click any node, or use “Trace it” to follow waste → process → resource paths. Every conversion metric from the sample — efficiency, diversion, yield, energy, carbon, value, demand — is shown in full below.

      Connect your own backend

      This static app works standalone. If you are running the platform locally or on a server, point it at your services and it will probe them — no credentials are stored.

      Run the stack with docker compose up from the repo root, then use the ports above. Browsers block plain-HTTP calls from an HTTPS Pages site — if a probe is blocked, that is mixed-content protection, not a backend failure; run this page locally (same folder, python3 -m http.server) for local backends.
